# 웹사이트 전체 디버깅 체크리스트 (v2.0)

이 문서는 동서화학 웹사이트의 프론트엔드 및 백엔드 기능 전반에 대한 디버깅 체크리스트입니다. `functionality_summary.md`의 최신 명세를 기반으로 작성되었으며, 기능 테스트, 버그 재현, 유지보수 시 활용하여 시스템의 안정성을 확보하는 것을 목적으로 합니다.

---

## Part 1: 프론트엔드 (Frontend)

### 1.1. 공통 UI 및 레이아웃

- [ ] **HTML 유효성**: `header`, `nav`, `section` 등 시맨틱 태그가 의미에 맞게 사용되었는지 확인.
- [ ] **이미지 및 리소스 경로**: `<img>` 태그, CSS `background-image`, `<script>`, `<link>` 등의 모든 경로가 올바르고, 깨진 리소스(404) 없이 정상 로드되는지 확인.
- [ ] **반응형 디자인**:
  - [ ] **Desktop/Tablet/Mobile**: 브라우저 크기를 조절하며 각 분기점에서 레이아웃(Flexbox/Grid), 폰트 크기, 이미지 등이 깨지지 않고 의도대로 표시되는지 테스트.
  - [ ] **모바일 네비게이션**:
    - [ ] 햄버거 버튼이 정상적으로 열리고 닫히는지 확인.
    - [ ] 메뉴 내 아코디언 서브메뉴(`toggleMobileSubmenu`)가 올바르게 작동하는지 확인.
    - [ ] 메뉴 항목 클릭 시 해당 섹션으로 이동하고 메뉴가 닫히는지 확인.
- [ ] **다국어 (`toggleLanguage`)**: `ENG/KOR` 버튼 클릭 시 모든 UI 텍스트가 정상적으로 변경되는지 확인. 특히, 최근 수정된 안내 문구 등이 `translations` 객체에 올바르게 반영되었는지 확인.

#### 1.2.1. 주요 섹션 UI/UX

- [ ] **페이지 탐색 (`navigateTo`)**: Header 및 Footer 메뉴 클릭 시 해당 섹션으로 부드럽게 스크롤되는지 확인.
- [ ] **히어로 캐러셀**:
  - [ ] 이전/다음 버튼 및 하단 점(dot)들이 정상 작동하는지 확인.
  - [ ] 5초 간격 자동 슬라이드 및 수동 조작 시 타이머가 초기화되는지 확인.
- [ ] **모달 및 팝업**:
  - [ ] **제품 상세 모달**: 제품 카드 클릭 시 `showProductDetail` 함수가 올바른 정보로 모달을 띄우고, 닫기 기능이 정상 작동하는지 확인.
  - [ ] **MSDS 안내 팝업**: 사이트 첫 방문 시 안내 팝업이 나타나는지, '자료실 가기'와 '닫기' 기능이 정상 작동하는지 확인.
- [ ] **카카오맵 렌더링**: '회사소개' 섹션 진입 시 카카오맵이 깨지지 않고 올바르게 렌더링되며, 길찾기/공유 버튼이 올바르게 동작하는지 확인.
- [ ] **상표 및 인증 갤러리**: '상표 및 인증 현황' 섹션(`id="certificates"`)에서 모든 인증서 이미지가 동적으로 정상 로드되는지 확인.
- [ ] **갤러리 섹션 (`id="gallery"`)**:
  - [ ] **콘텐츠 로드**: 'Professional's Choice' 섹션이 정상적으로 표시되는지 확인.
  - [ ] **이미지 로드**: 아티스트 협업 이미지(두산, 까르띠에 등)가 깨짐 없이 모두 표시되는지 확인.
  - [ ] **저작권 문구**: 모든 이미지 우측 하단에 저작권 문구가 올바르게 표시되는지 확인.
  - [ ] **UI 효과**: 마우스 오버 시 카드 상승 및 이미지 확대 효과가 부드럽게 작동하는지 확인.

## Part 2: 백엔드 (Backend - Netlify Functions)

### 2.1. API 엔드포인트별 기능

- [ ] **`login`**:
  - [ ] **성공**: 올바른 `password` 전송 시, 200 OK 응답과 유효한 JWT를 포함한 `{ "token": "..." }` 객체를 반환하는지 확인.
  - [ ] **실패**: 잘못된 `password` 전송 시, 401 Unauthorized 에러와 `{ "error": "..." }` 메시지를 반환하는지 확인.
- [ ] **`submit-inquiry`**:
  - [ ] **성공**: 필수 필드가 포함된 요청 시, 200 OK 응답과 함께 DB에 데이터가 정상 저장되는지 확인. `password`는 해시되어 저장되어야 함.
  - [ ] **실패**: 필수 필드 누락 시, 400 Bad Request 에러를 반환하는지 확인.
- [ ] **`get-public-list`**:
  - [ ] **사용자**: `getAll=true` 쿼리 파라미터가 없을 때, `is_public`이 true인 문의만 반환하고, 작성자 이름이 마스킹 처리되었는지 확인.
  - [ ] **관리자**: `getAll=true` 파라미터가 있을 때, 모든 문의를 반환하는지 확인 (JWT 인증 필요).
- [ ] **`get-msds-list`**:
  - [ ] **성공**: DB의 MSDS 게시글 목록을 최신순으로 반환하는지 확인.
  - [ ] **검색**: `?keyword=` 쿼리 파라미터가 있을 때, 제목 또는 내용에 키워드가 포함된 게시물만 필터링하여 반환하는지 확인.
- [ ] **`get-msds-detail`**:
  - [ ] **조회수 증가**: `?skipIncrement=true` 파라미터가 없을 때, `view_count`가 1 증가하는지 확인.
  - [ ] **조회수 유지**: `?skipIncrement=true` 파라미터가 있을 때, `view_count`가 증가하지 않는지 확인 (관리자 수정용).
- [ ] **`verify-password`**:
  - [ ] **성공**: `inquiryId`와 `password`가 일치할 때, `success: true`를 반환하는지 확인.
  - [ ] **실패**: 비밀번호 불일치 시, 401 Unauthorized 에러를 반환하는지 확인.
- **모든 관리자용 API (`admin-reply`, `create/update/delete-msds-post`, `delete-inquiry`)**:
  - [ ] **권한 (JWT)**: `Authorization: Bearer <token>` 헤더에 유효한 JWT를 포함하여 요청 시, 기능이 정상 수행되는지 확인.
  - [ ] **실패 (Unauthorized)**: 토큰이 없거나, 만료되었거나, 잘못된 토큰으로 요청 시, 401 Unauthorized 에러를 반환하는지 확인.
  - [ ] **입력값 검증**: 각 API가 필요한 ID, 제목, 내용 등의 입력값이 누락되었을 때 400 Bad Request 에러를 반환하는지 확인.

### 2.2. 데이터베이스 및 보안

- [ ] **DB 연결**: 모든 함수가 DB에 안정적으로 연결되는지, 연결 실패 시 500 에러와 함께 로그를 남기는지 확인.
- [ ] **비밀번호 해싱**:
  - [ ] **문의 등록**: `submit-inquiry` 시 사용자 비밀번호가 `bcrypt.hash`를 통해 해시되어 DB에 저장되는지 확인.
  - [ ] **비밀번호 검증**: `verify-password` 시 `bcrypt.compare`를 사용하여 입력된 비밀번호와 해시된 비밀번호를 비교하는지 확인.
- [ ] **XSS 방지**:
  - [ ] **입력**: `sanitize-html` 라이브러리 등을 사용하여 사용자 입력(문의 내용, MSDS 본문 등)이 DB에 저장되기 전 잠재적 스크립트가 제거되는지 확인.
  - [ ] **출력**: 혹은, 프론트엔드에서 `textContent`나 `sanitizeHTML` 유틸리티 함수를 사용해 데이터를 안전하게 렌더링하는지 확인. (현재 프로젝트는 후자 방식)
- [ ] **민감 정보 노출**: 어떤 API 응답에도 사용자의 비밀번호나 관리자 비밀번호의 해시값이 포함되지 않는지 확인.
- [ ] **환경 변수**: `ADMIN_PASSWORD_HASH`, `JWT_SECRET`, `DATABASE_URL` 등 모든 민감 정보가 소스 코드에 하드코딩되지 않고 Netlify 환경 변수로 안전하게 관리되고 있는지 확인.
- [ ] **에러 처리**: 모든 함수 내 `try-catch` 블록이 예외 상황(DB 에러, 권한 없음 등)을 처리하고, 일관된 형식의 에러 메시지(e.g., `{ "error": "..." }`)와 적절한 HTTP 상태 코드를 반환하는지 확인.
